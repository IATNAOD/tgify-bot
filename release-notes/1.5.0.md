# 1.5.0

## API Updates

- Support for [API 10.3](https://core.telegram.org/bots/api-changelog#august-24-2026), including everything added since API 9.4.
- All methods and update types up to this API version are now fully supported.

## New methods

- `sendRichMessage`, `sendRichMessageDraft` - rich messages built from blocks, HTML or Markdown
- `sendLivePhoto` - live photos; they can also be sent in `sendMediaGroup`, `sendPaidMedia` and `editMessageMedia`
- `editEphemeralMessageText`, `editEphemeralMessageMedia`, `editEphemeralMessageCaption`, `editEphemeralMessageReplyMarkup`, `deleteEphemeralMessage` - ephemeral messages, visible only to one user of a group
- `answerGuestQuery` - replies in guest mode, in chats the bot isn't a member of
- `answerChatJoinRequestQuery`, `sendChatJoinRequestWebApp` - join requests assigned to the bot
- `getManagedBotToken`, `replaceManagedBotToken`, `getManagedBotAccessSettings`, `setManagedBotAccessSettings` - bots managed by your bot
- `deleteMessageReaction`, `deleteAllMessageReactions`, `setChatMemberTag`, `getUserPersonalChatMessages`, `savePreparedKeyboardButton`

Context shorthands take the identifiers from the current update:

- `ctx.sendRichMessage()` / `ctx.replyWithRichMessage()`, `ctx.sendRichMessageDraft()`, `ctx.sendLivePhoto()` / `ctx.replyWithLivePhoto()` (both `replyWith*` also work with `useNewReplies()`)
- `ctx.editEphemeral*()` and `ctx.deleteEphemeralMessage()` - for the ephemeral message of the update, e.g. the one whose button was pressed
- `ctx.answerGuestQuery(result)` - in a `guest_message` update
- `ctx.answerChatJoinRequestQuery(result)`, `ctx.sendChatJoinRequestWebApp(url)` - in a `chat_join_request` update
- `ctx.deleteMessageReaction()` - in a `message_reaction` update removes that reaction, otherwise pass `{ user_id }` or `{ actor_chat_id }`
- `ctx.deleteAllMessageReactions()`, `ctx.setChatMemberTag()`

Ephemeral messages are sent by the usual methods with `ephemeral_message_parameters`; `ctx.reply()` never makes a message ephemeral on its own:

```TS
const { Tgify, Markup } = require("@tgify/bot");

const BOT_TOKEN = "xxx:xxx";

const bot = new Tgify(BOT_TOKEN);

bot.command("secret", (ctx) =>
	ctx.reply("Only you can see this", {
		ephemeral_message_parameters: { receiver_user_id: ctx.from.id },
		...Markup.inlineKeyboard([Markup.button.callback("Hide", "hide")]),
	}),
);

bot.action("hide", (ctx) => ctx.deleteEphemeralMessage());

bot.launch();

// Enable graceful stop
process.once("SIGINT", () => bot.stop("SIGINT"));
process.once("SIGTERM", () => bot.stop("SIGTERM"));
```

Rich messages are plain objects, as described in the Bot API:

```TS
bot.command("news", (ctx) =>
	ctx.replyWithRichMessage({
		blocks: [
			{ type: "heading", text: "Weekly news", size: 1 },
			{ type: "photo", photo: { type: "photo", media: { source: "./cover.jpg" } } },
			{ type: "paragraph", text: "Everything that happened this week." },
		],
	}),
);
```

## New updates

- `guest_message` - `ctx.guestMessage` and the `guestMessage(...)` filter; `ctx.msg`, `ctx.chat`, `ctx.from` and `ctx.text` work with it too
- `managed_bot` - `ctx.managedBot`, `ctx.from` is the user who created the bot
- `subscription` - `ctx.subscription`, `ctx.from` is the subscriber
- `stopped_message_generation` - `ctx.stoppedMessageGeneration`, `ctx.chat` is the chat of the draft

```TS
const { guestMessage } = require("@tgify/bot/filters");

bot.on(guestMessage("text"), (ctx) =>
	ctx.answerGuestQuery({
		type: "article",
		id: "1",
		title: "Echo",
		input_message_content: { message_text: ctx.guestMessage.text },
	}),
);
```

## Formatting and keyboards

- `Format.dateTime(text, unixTime, format?)` - a date shown to each user in their own format; `format` is checked by TypeScript (`"wDT"`, `"t"`, `"r"`, ...)
- `Extensions.entity` handles `date_time`: `toHTML` writes `<tg-time>`, `toMarkdownV2` writes `![...](tg://time?...)`, `parse_html` reads `<tg-time>`
- `Markup.button.managedBotRequest(text, requestId, extra?)` - asks the user to create a bot managed by yours
- `Markup.button.disabled(text)` - an inline button that does nothing
- `.forceReply()` on `Markup.keyboard(...)` and `Markup.inlineKeyboard(...)` - also opens the reply interface

```TS
const { fmt, bold, dateTime } = require("@tgify/bot/format");

bot.command("event", (ctx) =>
	ctx.reply(fmt`${bold("Meetup")} starts ${dateTime("tomorrow at 18:00", 1793458800, "wDT")}`),
);
```

## Files inside objects

Files are now uploaded wherever the Bot API accepts them inside objects, not only as `media` of media groups:

- the `photo` of live photos and the `cover` of videos in `sendMediaGroup`, `sendPaidMedia`, `editMessageMedia` and `editEphemeralMessageMedia`
- media of polls and poll options in `sendPoll` and `sendQuiz`
- media of rich messages, in blocks and in `media`
- `setMyProfilePhoto`, `setBusinessAccountProfilePhoto`, `postStory`, `editStory`
- stickers in `createNewStickerSet` and `addStickerToSet`

Previously these were sent as JSON and the upload failed.

## Fixes

- Object parameters such as `reply_parameters` were silently dropped from requests that upload a file. They are sent now
- `answerWebAppQuery` and `savePreparedInlineMessage` with an article that has a `url` downloaded that page and sent it as a file
- `Extensions.entity.parse_html`: custom emoji identifiers lost precision (`5368324170671202286` became `5368324170671202000`), and unquoted attribute values such as `emoji-id=5368324170671202286` were rejected

## Worth knowing when updating

- Polls: the Bot API replaced `correct_option_id` with `correct_option_ids`. `sendPoll` and `sendQuiz` still accept `correct_option_id` and convert it, but it's deprecated. Received polls have `correct_option_ids` instead
- `ReplyParameters.message_id` is optional now, since replies to ephemeral messages use `ephemeral_message_id`
- `ctx.editMessageText()` accepts `undefined` as the text when `rich_message` is passed
- `Extensions.entity.parse_html` throws on mismatched closing tags such as `<b><i>x</b></i>`, as Telegram does
