# 1.4.0

## Extensions

Tgify now ships optional building blocks, available as `Extensions` from the package root (or from `@tgify/bot/extensions`):

- `Extensions.ratelimit` - limits how often updates from the same user reach your handlers
- `Extensions.storage` - Redis and MongoDB session stores
- `Extensions.entity` - converts message entities to HTML / MarkdownV2 and parses markup into entities

### Rate limiting

```TS
const { Tgify, Extensions } = require("@tgify/bot");

const BOT_TOKEN = "xxx:xxx";

const bot = new Tgify(BOT_TOKEN);

bot.use(
	Extensions.ratelimit({
		window: 3000, // ms
		limit: 1, // updates per window and user
		onLimitExceeded: (ctx) => ctx.reply("Too many requests, slow down"),
	}),
);

bot.start((ctx) => ctx.reply("Start"));

bot.launch();

// Enable graceful stop
process.once("SIGINT", () => bot.stop("SIGINT"));
process.once("SIGTERM", () => bot.stop("SIGTERM"));
```

- Works without `session()`: counters are kept in memory and cleaned up automatically
- `keyGenerator` changes whose updates are counted together (the sender by default)
- `store` accepts any session store, e.g. `Extensions.storage.Redis(...)`, to share the limit between several bot instances

### Persistent sessions

Database drivers aren't installed with Tgify, so the package stays light. Install the one you use:

```shellscript
$ npm install redis    # for Extensions.storage.Redis
$ npm install mongodb  # for Extensions.storage.Mongo
```

If the driver is missing, creating the store throws an error with the install command.

```TS
const { Tgify, session, Extensions } = require("@tgify/bot");

const BOT_TOKEN = "xxx:xxx";

const bot = new Tgify(BOT_TOKEN);

bot.use(
	session({
		defaultSession: () => ({ messages: 0 }),
		store: Extensions.storage.Redis({
			url: "redis://127.0.0.1:6379",
			ttl: 7 * 24 * 60 * 60 * 1000, // optional: forget sessions not saved for a week
		}),
		// OR store: Extensions.storage.Mongo({ url: "mongodb://127.0.0.1:27017", database: "bot" }),
	}),
);

bot.on("message", (ctx) => ctx.reply(`Messages: ${++ctx.session.messages}`));

bot.launch();

// Enable graceful stop
process.once("SIGINT", () => bot.stop("SIGINT"));
process.once("SIGTERM", () => bot.stop("SIGTERM"));
```

Both stores accept an existing client (`{ client }`) instead of `url`, and `onInitError` to handle connection errors.

### Entities

```TS
const { Tgify, Extensions } = require("@tgify/bot");
const { message } = require("@tgify/bot/filters");

const BOT_TOKEN = "xxx:xxx";

const bot = new Tgify(BOT_TOKEN);

// echo the message back with its formatting
bot.on(message("text"), (ctx) => ctx.replyWithHTML(Extensions.entity.toHTML(ctx.message)));

bot.launch();

// Enable graceful stop
process.once("SIGINT", () => bot.stop("SIGINT"));
process.once("SIGTERM", () => bot.stop("SIGTERM"));
```

`Extensions.entity.toMarkdownV2` does the same for MarkdownV2, `Extensions.entity.parse_html` and `parse_markdown` turn markup into `{ text, entities }`.

## Concurrent long polling

By default, each batch of updates is handled completely before the next one is fetched, so one slow handler delays the whole bot. You can now let updates be fetched while earlier ones are still being handled:

```TS
bot.launch({ polling: { concurrency: 10 } }); // at most 10 updates handled at the same time
```

Note that in this mode updates are confirmed to Telegram before they're handled, so updates in progress are lost if the process crashes. Without the option, polling works as before.

## Sessions in memory

`MemorySessionStore` with a `ttl` now cleans up expired sessions of inactive users, so memory stays bounded. The default store still keeps sessions forever; pass a ttl explicitly if your bot runs for long:

```TS
const { session, MemorySessionStore } = require("@tgify/bot");

bot.use(session({ store: new MemorySessionStore(7 * 24 * 60 * 60 * 1000) }));
```

## Fixes

- `ctx.businessConnection` - the getter was spelled with a Cyrillic "С", so `ctx.businessConnection` returned `undefined`. The old spelling still works and is deprecated
- `ctx.sendGift()` now works in channel posts and sends the gift to the channel
- `ctx.giftPremiumSubscription()` reports its own name in errors, its parameters are documented correctly
- `ctx.persistentChatAction()` documents the actual default interval, 4000 ms

## Worth knowing when updating

- Debug logs now all use the `tgify:` prefix. If you enabled them with `DEBUG=telegraf:*`, use `DEBUG=tgify:*`
- Node.js 18 or newer is required
